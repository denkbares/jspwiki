# Browser array conversion 🍺

The default template loads `scripts/haddock.js`, generated by the Maven wro4j execution from
`src/main/config/wro/wro-haddock.xml`. Its library group loads MooTools Core 1.6 before More and the
JSPWiki extensions. Core preserves an existing `Array.from`: modern callers need iterable conversion,
Unicode code points, array copies and the mapping callback with `thisArg`. The old fallback is installed
only when the browser has no `Array.from`; it is not a standards-complete polyfill.

MooTools callers needing null-to-empty, scalar wrapping or array identity use `Array.convert`.
The vendored Core/More sources already use it. The remaining JSPWiki `Array.from` calls consume
`arguments` (String.Extend, Textarea, MooEditable and its MenuList) or select options (Element.Extend);
these inputs also work with native conversion. No caller migration was necessary.

The separately shipped template 210 loads `src/main/webapp/scripts/mootools.js`; it does not replace
native `Array.from`. KnowWE's older interview HTML resources load Prototype in their own documents,
not through this template. They are outside the Haddock runtime change.

## Build and verification

Run `mvn -pl jspwiki-war -am install` from the JSPWiki root to rebuild the actual WAR, then rebuild the
consuming KnowWE/KONAP WAR. Editing the source alone does not update an existing deployed `haddock.js`.

KONAP-UITests `tests/ui/platform/array-from-runtime.spec.ts` checks the actual served scripts: native
function identity, Map/Set/generators, mapping and `thisArg`, NodeLists, supplementary Unicode, array
copying, legacy conversions and real JSPWiki string/select helpers. It also loads the shipped template
210 script in a separate page, and exercises the no-native fallback. It does not test the complete 210
template or interview application. Run it in the normal Playwright `ui` project against the rebuilt WAR.
